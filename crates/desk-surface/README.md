# desk-surface

The surface protocol (`specs/surface/v0`, ADR 0141) as Rust types: the one contract between the
compositor and anything that draws a surface. A web surface's host (CEF off-screen, #52) speaks it
today; a native plugin's process will in Stage 3 (#59). Engine-neutral, `serde` only: no GPU, engine
or OS dependency, so the compositor, `desk-web` and a native plugin all depend on it.

## Public API

- `CompositorMessage`: what the compositor sends. `create`, `resize`, `show`, `hide`, `sleep`, `wake`,
  `destroy`; `release` of a frame's texture; `pace` (the most frames per second); pointer, key and
  focus input in the surface's logical pixels; IME composition, commit and cancel; drag enter, over,
  leave, drop and ended (ADR 0119); `a11y.enable` and `a11y.action`.
- `SurfaceMessage`: what a surface sends. `ready`, `died`, `title`; `attach` (a `SurfaceTexture`
  with its `SurfaceTextureHandle`: IOSurface, D3D11 shared handle or DMA-BUF, damage and when it
  comes back); `rate`; `cursor`; `ime.enabled` and `ime.caret`; `drag.accept`, `drag.start`,
  `drag.status`, `drag.done`; `a11y.update` (AccessKit's `TreeUpdate` shape).
- `generated`: every type of the spec, GENERATED by `just codegen` from `specs/surface/v0`; never
  edit it by hand. Each message is one JSON object (`serde_json`); file descriptors and Mach rights
  travel beside it, named by index.

The pages of `specs/surface/v0` (lifecycle, texture, input, ime, accessibility) say what each message
means and who sends it when.

## Test

```bash
cargo test -p desk-surface
```

`tests/vectors.rs` judges every vector of `specs/surface/v0/vectors` by the schemas, reads each
valid one through the generated types and writes it back unchanged, and checks that the types refuse
what is wrong in shape (a message sent the wrong way, an unknown field). The TypeScript side holds
the same vectors in `packages/bridge/src/surface.contract.test.ts`.
