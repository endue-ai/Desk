# desk-bridge

Rust side of the Desk bridge: the types generated from `specs/bridge/v0`, `specs/plugin/v0`,
`specs/item/v0`, `specs/view/v0`, `specs/connector/v0` and `specs/init/v0`.

Layer: Desk bridge (see `docs/architecture.md`). Status: generated types only; traits arrive with the core.

## Public API

- Request, response and event types: `BridgeRequest`, `BridgeResponse`, `BridgeEvent`, and one
  `*Request` / `*Params` / `*Result` per method (`FsReadRequest`, `ProcSpawnParams`, ...).
- The permission vocabulary (`Permission` and one struct per permission) and `PluginManifest`.
- init.yaml: `InitDocument`, `InitPlugins`, `InitSettings`, `InitSync`.
- Items, views and connectors: `Item` (one variant per kind), `ItemQuery`, `ItemPage`, `ItemChange`,
  `View`, `ConnectorManifest`, `ConnectorInstance`, `ConnectorStatus`, `ConnectorSyncResult`.
- `view_problems(&View)` and `manifest_problems(&PluginManifest)`: the rules the schemas cannot say
  (a view's `$name` sources and `{params.<name>}` templates resolve; a connector's actions are
  commands it declares), one problem per line, each starting with its JSON pointer.
- `SCHEMAS`: every plugin, item, view, connector, init and bridge JSON Schema as `($id, json)` for
  validation at run time.
- `NAME`: the crate name.

`src/generated.rs` is GENERATED by `just codegen`; never edit it by hand.

## Testing

```bash
cargo test -p desk-bridge
```

`tests/contract.rs` checks the shared vectors (schemas and the rules above) and round trips;
`tests/wit.rs` checks that `specs/wit/desk-host.wit` is a subset of the bridge methods.
