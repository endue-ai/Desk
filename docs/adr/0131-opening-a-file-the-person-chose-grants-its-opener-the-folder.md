# Opening a file the person chose gives its opener read access to the file's folder, without asking

## Context and Problem Statement

Explorer opens a file through `desk.files.open`; the plugin the desk's rules name (Images, Docs,
Sheets, the player, …) reads it under its own grants. Most openers declare no `fs:read` paths, so the
first file of every folder failed its read, the opener asked with `perm.request` for the folder, and
the person had to answer a prompt for a file they had just clicked. A click in the file view is already
the person saying "show me this file". How does the desk let the opener read it without a prompt, and
without letting any caller hand itself access to the person's files?

## Decision Drivers

* Opening a file the person chose never asks
* Nothing reads more than the prompt would have offered: the openers ask for the file's folder
* An agent, or a plugin, cannot use an open to give itself or a plugin of its choice access
* Every primitive call still passes the permission check (architecture principle 6)

## Considered Options

* `perm.grant`: the runtime, a `perm:manage` holder, grants the opener the folder before its visit
* The runtime answers the opener's `perm.prompt` itself
* Built-in openers declare `fs:read` for the whole home folder
* Openers read through a token the runtime mints for the one file

## Decision Outcome

Chosen option: "`perm.grant`", because it states what happened (the person chose the file) at the one
place that knows it, and needs no change to the openers.

* **The method** (`specs/bridge/v0/perm.schema.json`): `perm.grant { caller, permission, duration?,
  reason?, scope: perm:manage }` answers `{ grant }`. A lasting grant that already covers the
  permission is the answer; an agent gets nothing outside its allowlist. The grant is logged and
  heard (`perm.changed`) like any other, and the person can revoke it in the permissions view.
* **Who chose** (`policies/files.ts`, `personChose`): the desk's own opens (keys, the palette, the file
  picker, recent files, a restored session), and a plugin's open (Explorer, Git, Notes' links) when the
  desk's rules pick the opener. Not an agent's (`agent:<id>`), and not a plugin's that names the plugin
  to open with (`plugin`), which could name itself.
* **What** (`folderRead`): `fs:read` on the file's folder (`<folder>/**`) for the session, the scope every
  opener already asks for, so one open covers its neighbours (Images' next and previous) as the prompt
  would have.
* If the grant fails (no `perm:manage`, an older core), the opener asks as before.

### Consequences

* Good, because a click in Explorer opens the file at once.
* Good, because the openers and their asks stay as they are, for files opened any other way.
* Bad, because opening a file directly in the home folder gives its opener the whole home folder for
  the session, as answering its prompt would have.
* Bad, because a plugin allowed to invoke `desk.files.open` can make the person's opener read a file
  the person did not pick; the file is shown to the person in that opener, never to the plugin.

## More Information

Writing is not covered: saving a file in another folder still asks the first time. Spec change:
`perm.grant` in `specs/bridge/v0` (types generated by `just codegen`); core `perm_grant` in
`crates/desk-core/src/core_perm.rs`; the stub core's in `packages/bridge/src/stub-grants.ts`.
