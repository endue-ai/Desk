# Document position and versioned Sheet saves

## Context and Problem Statement

The document tools read open files as a whole or in ranges. They lacked the view's current
position and the actions a person uses to navigate. A Sheets save generated bytes in the UI
plugin, so the file writer needed a way to apply the initiating agent's permission and Undo rule.

## Decision Drivers

- Use the rendered document, book, presentation or grid as the source of its current position.
- Share navigation, zoom, presentation and marking with the existing window controls.
- Validate a Sheets range edit completely before changing any cell.
- Route the exact Sheet save through the existing Core file approval and version history.

## Considered Options

- Reconstruct positions from an independent agent model and have the provider save under its own grant.
- Use the existing UI and editable document, and authenticate one file write with the initiating invocation.

## Decision Outcome

Docs reports the visible page, visible heading and document selection. Reader reports the page
or chapter and shares its bookmark and note store. Slides reports the slide in the active
presentation or browsing view. These navigation tools take one-based page, chapter and slide
numbers.

Sheets reads the visible worksheet and its A1 selection and active cell. Select and Find use
the same grid as the person. A range edit checks the complete rectangle against the format's
lossless fields and leaves the edit in the buffer.

An agent Save names the active workbook's exact path. Only the trusted built-in Sheets provider
can claim its pending invocation once, with the same path and one exact write scope. The core
runs that write as the initiating agent and publishes its versioned Undo receipt before leaving
the turn. The general file Save directs agents to the Sheets tool for these buffers. A person's
Save still commits the current formula-bar edit and uses its ordinary file permissions.
