# 보안 정책

## 취약점 제보

공개 이슈는 열지 말아 주십시오. 다음 중 한 가지 방법으로 비공개로 제보해 주십시오.

- 제목에 "security"를 넣어 team@endue.ai로 이메일을 보냅니다.
- 또는 이 저장소 Security 탭에 있는 GitHub의 "Report a vulnerability" 버튼을 사용합니다.

발견한 내용, 재현 방법, 영향을 받는 버전과 OS, 예상되는 영향을 함께 적어 주십시오.

## 이후 절차

| 단계 | 목표 시한 |
| --- | --- |
| 접수 확인 | 영업일 기준 3일 이내 |
| 1차 평가 및 심각도 판정 | 영업일 기준 10일 이내 |
| 수정 배포 | 심각도가 요구하는 만큼 빠르게 |
| 공개 | 수정이 배포될 때, 늦어도 제보 후 90일 이내 |

원하지 않는다고 알려 주지 않는 한, 릴리스 노트에 제보자를 기재합니다.

## 지원 버전

Desk는 1.0 이전 단계입니다. 각 채널(stable, beta, canary)의 최신 릴리스만 보안 수정을 받습니다.

## 범위

포함: 데스크톱 앱, Rust 크레이트, TypeScript 패키지, 내장 플러그인, 그리고 브리지 권한 모델(플러그인이나
에이전트가 권한 없이 프리미티브에 접근하는 것은 취약점입니다).

제외: 서드파티 플러그인, 그리고 이 저장소 밖의 서비스(이들은 같은 주소로 endue에 제보합니다).

## 위협 모델

[docs/security/threat-model.md](../../security/threat-model.md)(영문)에 Desk가 지키는 자산, 고려하는 공격자, 그리고
신뢰 경계마다 지금 `main`에 있는 대책이나 남은 빈틈과 그것을 메울 이슈를 정리해 두었습니다.
