# endue Desk 탐색기(Explorer) 요구사항

2026-10-31 · Team endue

> `desk-requirements.md` 의 시스템 플러그인 표에서 `files` 행이 비워 둔 자리, 곧 *허락한 폴더 보기(dired): 열기 · 드래그 · 감시* 를 채우는 문서입니다. 정책 플러그인 `desk.files`(여는 규칙 · 최근 파일 · 저장 · 되돌리기 · 디스크 변경)는 그대로 두고, 폴더 보기는 UI 플러그인 **`endue.explorer`**(`plugins/explorer`)가 맡습니다. 요구사항 한 줄이 Task 이슈 하나의 요구사항 칸이 됩니다. 코드와 어긋나면 이 문서를 고치고, 되돌리기 어려운 갈림길은 ADR 로 남깁니다.

탐색기는 파일을 *보여 주는* 플러그인이지 *읽는* 플러그인이 아닙니다. 목록(`fs.list`)과 감시(`fs.watch`)만 자기 권한으로 하고, 파일은 `desk.files.open` 으로 데스크에 넘겨 여는 규칙(`contributes.files`)이 고른 플러그인이 자기 grant 로 읽습니다. 그래서 탐색기를 다른 것으로 갈아끼워도 "무엇이 무엇을 여는가" 는 바뀌지 않습니다.

## 결정

| 갈림길 | 결정 | 이유 |
| --- | --- | --- |
| `desk.files` 안에 넣는가, 새 플러그인인가 | 새 UI 플러그인 `endue.explorer` | `desk.files` 는 데이터만 있는 정책 플러그인(ADR 0017). 폴더 보기는 코드가 있는 표면이고, 한 폴더 한 관심사. 끄고 다른 탐색기로 갈아끼울 수 있어야 한다(약속 2) |
| 이름 | Explorer · 탐색기 | VS Code 의 관용어. "Files" 는 `desk.files` 가 쓰고, Finder 는 Apple 의 이름 |
| 파일을 누가 읽는가 | 탐색기는 목록만. 열기는 `desk.files.open` | 탐색기가 모든 파일을 읽을 이유가 없다(약속 4). 여는 규칙은 한 곳에 |
| 권한의 폭 | 매니페스트는 `${home}/**` 를 *선언*, 호출은 폴더 단위 scope, 거절되면 그 폴더 하나만 묻는다 | 선언은 상한이고 허락은 폴더마다다 — "허락한 폴더 보기". `endue.notes` 와 같은 패턴 |
| 상태를 어디에 두는가 | 폴더 목록 · 숨김 · 페이지는 settings, 펼친 폴더 · 선택은 store | 설정은 사람이 바꾸는 값이라 init.yaml 과 설정 UI 가 본다. store 는 플러그인의 작업 상태 |
| 자리 | 표면 `left` 하나 | 탐색기의 관용 자리. 셸의 에이전트 바와의 관계는 ADR 0028 에 맡긴다(§열린 질문) |
| 쓰기 작업의 범위 | 1단계는 *새 파일* 만. 이름 바꾸기 · 옮기기 · 복사 · 삭제 · 새 폴더는 브리지에 메서드가 생긴 뒤 | bridge v0 의 fs 는 `read` · `write` · `list` · `watch` 넷뿐이다(§명세에 필요한 것). 우회(빈 `.keep` 파일로 폴더 만들기 등)는 하지 않는다 |
| 공개 SDK 만 | 커뮤니티 플러그인과 같은 형식, 런타임 내부 API 없음 | 규칙 9. 탐색기가 되면 커뮤니티 탐색기도 된다 |

## 필수 기능

1단계(지금 `plugins/explorer`)에 들어가는 것입니다. 전부 bridge v0 그대로 됩니다.

1. **트리**: 허락한 폴더들이 루트. 펼칠 때 그 폴더만 `fs.list`(지연 로드), 접어도 목록은 남는다. 폴더 먼저, 그 안은 자연 정렬(`a2` < `a10`), 대소문자 무시.
2. **숨김 항목**: 점으로 시작하는 이름은 기본 숨김. 커맨드 · 도구 버튼 · 설정으로 토글.
3. **열기**: Enter · Space · 클릭 → `desk.files.open { path }`. 여는 플러그인이 없으면 데스크가 알리고 탐색기도 상태 줄에 적는다.
4. **키보드**: WAI-ARIA tree 패턴. ↑↓ 이동, → 펼치기 또는 첫 자식, ← 접기 또는 부모, Home · End, Enter · Space, 글자를 치면 다음 일치 항목으로(type-ahead). Mod 코드는 데스크로 통과(`Mod+O` · `Mod+S` · `Mod+W`).
5. **감시**: 펼친 폴더마다 `fs.watch`(비재귀). 변경은 묶어서(디바운스) 그 폴더만 다시 나열. 상한 64개(v0 에 unwatch 가 없다).
6. **권한**: 거절되면 그 폴더 하나(`<folder>/**`)로 `perm.request`, 다시 거절되면 행과 상태 줄에 문장으로. 재시도는 사람이 다시 눌렀을 때만(시작마다 묻지 않는다).
7. **폴더 추가 · 제거**: 팔레트에 경로를 치면(`desk.palette.pick`, free) 정규화 → 허락 요청 → 나열. 이미 보이는 폴더 안이면 추가하지 않고 그 자리를 펼친다. 설정 `endue.explorer.folders` 에 보존.
8. **새 파일**: 선택한 폴더(파일을 선택했으면 그 폴더)에 빈 파일. 쓰기 전에 폴더를 **다시 나열**해 같은 이름이 있으면 거절한다 — 캐시된 목록으로 덮어쓰기를 판단하지 않는다. 만든 뒤 선택하고 연다.
9. **드러내기**: `Mod+Shift+R` → 쓰는 중인 파일(`desk.buffers.list` 의 첫 버퍼)까지 펼치고 선택, 표면을 보인다. `{ path }` 로 다른 파일도. 폴더 밖이면 문장으로.
10. **드래그**: 행을 끌면 `text/plain` 과 `application/x-desk-path` 로 경로 문자열을 내보낸다. 내용은 내보내지 않는다. 받는 쪽(셸의 드롭존 · 표면)은 각자의 일.
11. **큰 폴더**: 한 번에 `page`(기본 500)개, "N more" 행으로 다음 페이지. 선택은 새로 보인 첫 행으로.
12. **보존**: 펼친 폴더 · 선택은 store 에, 재시작 때 복원(루트 밖은 버림). 저장한 선택은 폴더가 나열될 때까지 기다린다.
13. **상태 줄**: `role=status`, 실패는 전부 문장으로("Not allowed to list ~/Documents."). 다음 성공이 비운다.
14. **커맨드 7개 · 키 2개**: `endue.explorer.{open,reveal,refresh,toggle-hidden,add-folder,remove-folder,new-file}`, `Mod+Shift+E` · `Mod+Shift+R`. 팔레트 · 키 · Eris · 에이전트 · 도구 버튼이 같은 id 를 부른다(약속 3). `desk.keys` 의 기본 키맵과 겹치지 않는다(테스트가 잡는다).

## 요구사항

*현재* 는 `plugins/explorer` 의 첫 PR 기준(있음 · 일부 · 없음), *단계* 는 `desk-requirements.md` §단계의 번호입니다.

### 보기 (EXP-01 ~ 09)

| ID | 요구사항 | 현재 | 단계 |
| --- | --- | --- | --- |
| EXP-01 | 허락한 폴더들을 루트로 하는 트리. 루트는 설정 `endue.explorer.folders`(기본 `["~/Documents"]`), init.yaml 과 설정 UI 가 바꾼다 | 있음 | 1 |
| EXP-02 | 지연 로드: 폴더는 처음 펼칠 때만 `fs.list`, 접어도 목록은 남고 다시 펼치면 호출 없음 | 있음 | 1 |
| EXP-03 | 정렬: 폴더 먼저 → 파일 · 링크. 각각 자연 정렬 · 대소문자 무시, 대소문자만 다른 이름은 고정 순서 | 있음 | 1 |
| EXP-04 | 숨김 항목(점 시작)은 기본 숨김, `endue.explorer.show-hidden` 으로 토글 · 보존 | 있음 | 1 |
| EXP-05 | 페이지: 폴더마다 `endue.explorer.page`(기본 500)개까지, "N more" 행이 다음 페이지를 연다 | 있음 | 1 |
| EXP-06 | 행마다 종류(폴더 · 파일 · 링크)와 파일 크기. 심링크는 "link" 로 표시하고 펼치지 않는다(대상 종류를 모른다) | 있음 | 1 |
| EXP-07 | 심링크의 대상 종류 · 끊어짐 표시, 수정 시각 · 권한 열 | 없음 (`fs.stat` 필요) | 2 |
| EXP-08 | 정렬 기준 선택: 이름 · 수정 시각 · 크기 · 종류, 폴더별이 아닌 전역 설정 | 없음 (`modifiedAt` 필요) | 2 |
| EXP-09 | 가상화: 보이는 행만 DOM 에. 1만 행 폴더에서 스크롤 60fps | 없음 | 2 |

### 입력 (EXP-10 ~ 14)

| ID | 요구사항 | 현재 | 단계 |
| --- | --- | --- | --- |

### 열기 · 드래그 (EXP-20 ~ 24)

| ID | 요구사항 | 현재 | 단계 |
| --- | --- | --- | --- |
| EXP-20 | 파일은 `desk.files.open { path }` 로 연다. 탐색기는 `fs.read` 를 호출하지 않는다 | 있음 | 1 |
| EXP-21 | 여는 플러그인이 없는 파일: 데스크의 경고 + 탐색기 상태 줄 문장. 탐색기가 대신 열지 않는다 | 있음 | 1 |
| EXP-22 | 드래그 내보내기: `text/plain` · `application/x-desk-path` = 경로 문자열. 내용 · 파일 객체는 내보내지 않는다 | 있음 | 1 |
| EXP-23 | "다른 플러그인으로 열기": 여는 규칙을 가진 플러그인 목록에서 고르기(`desk.files.open { path, plugin }`) | 없음 (`cmd.list` 로 opener 조회 필요) | 2 |
| EXP-24 | 드롭 받기: 표면 · OS 에서 탐색기 폴더로 떨어진 파일을 옮기거나 복사 | 없음 (`fs.copy` · `fs.rename` 필요) | 2 |

### 감시 (EXP-30 ~ 33)

| ID | 요구사항 | 현재 | 단계 |
| --- | --- | --- | --- |
| EXP-30 | 펼친 폴더마다 `fs.watch`(비재귀), `fs.changed` 는 그 폴더만 다시 나열 | 있음 | 1 |
| EXP-31 | 디바운스: 한 폴더의 연속 변경은 한 번의 `fs.list` 로. 접힌 폴더 · 모르는 watch 의 이벤트는 무시 | 있음 | 1 |
| EXP-32 | 감시 상한 64개. 넘으면 그 폴더는 펼칠 때만 새로 나열. `fs.watch` 거절 · 실패여도 트리는 동작 | 있음 | 1 |
| EXP-33 | 접을 때 감시를 끝내고, 제거한 폴더의 감시도 끝낸다 | 없음 (`fs.unwatch` 필요) | 2 |

### 권한 · 안전 (EXP-40 ~ 46)

| ID | 요구사항 | 현재 | 단계 |
| --- | --- | --- | --- |
| EXP-40 | 매니페스트 선언은 `fs:read` · `fs:write` 각 `${home}/**`, `cmd:invoke` 는 코드가 실제로 부르는 `desk.files.open` · `desk.buffers.list` · `desk.palette.pick` 셋만. 선언과 호출의 일치를 테스트가 잡는다 | 있음 | 1 |
| EXP-41 | 모든 fs 호출의 scope 는 그 경로가 속한 루트의 `<root>/**`. 루트 밖 경로는 부모 폴더로 | 있음 | 1 |
| EXP-42 | 거절(`permission_denied`)은 한 번 `perm.request`(이유 문장 포함), 다시 거절되면 행 · 상태 줄에 문장. `not_found` 등 다른 오류는 묻지 않고 코드와 함께 적는다 | 있음 | 1 |
| EXP-43 | 새 파일은 쓰기 직전에 폴더를 다시 나열해 같은 이름이면 거절. `fs.write` 는 덮어쓰기라서 캐시로 판단하면 자료를 잃는다 | 있음 (경쟁 조건은 남음 — `fs.write { exclusive }` 로 닫는다) | 1 · 2 |
| EXP-44 | 경로는 브리지 `Path` 형식(`/` · `~` · `C:/` · `${...}`)만 받고, `..` 세그먼트와 상대 경로는 거절. 백슬래시는 `/` 로 | 있음 | 1 |
| EXP-45 | 사람이 폴더의 grant 를 회수(`perm.changed`)하면 그 폴더의 목록을 비우고 "다시 허락" 행으로 | 없음 | 2 |
| EXP-46 | 에이전트가 커맨드로 탐색기를 움직일 때(`endue.explorer.reveal` · `.add-folder`) 폴더 추가는 사람의 `perm.request` 승인 없이는 나열되지 않는다 — 코어의 권한 검사가 보장 | 있음 (코어) | 1 |

### 쓰기 작업 (EXP-80 ~ 86, 2단계)

전부 브리지 명세가 먼저입니다(§명세에 필요한 것). 각 작업은 커맨드 하나 · 확인 질문 하나(`desk.palette.pick`) · 되돌리기 가능한 것은 되돌리기.

## 명세에 필요한 것 (`specs/bridge/v0`, 유지보수자의 몫)

bridge v0 의 fs 는 `read` · `write` · `list` · `watch` 넷이고, 권한 어휘는 `fs:write` 를 "만들고 덮어쓰고 **삭제**" 라고 적지만 삭제 메서드가 없습니다. 2단계의 쓰기 작업은 아래가 먼저 명세에 들어가야 합니다. `specs/` 는 CODEOWNERS 가 잠근 곳이라 탐색기 PR 이 아니라 별도 이슈로 냅니다. 순서는 쓰임이 많은 것부터.

| 메서드 · 필드 | 쓰는 요구사항 | 비고 |
| --- | --- | --- |
| `fs.stat { path }` → kind · size · modifiedAt · target(링크) | EXP-07 · 08 | 심링크를 펼칠 수 있게 하는 유일한 길 |
| `DirEntry.modifiedAt` | EXP-08 | `fs.list` 한 번으로 정렬. `stat` N 번은 큰 폴더에서 못 쓴다 |
| `fs.write { exclusive: true }` → `already_exists` | EXP-43 | 새 파일의 경쟁 조건을 코어에서 닫는다 |
| `fs.unwatch { watchId }` | EXP-33 | 감시 상한 64개를 없앤다 |
| `fs.mkdir { path }` | EXP-80 | |
| `fs.rename { from, to }` | EXP-81 · 82 | 같은 scope 안에서만. 열린 버퍼의 경로 갱신은 `desk.buffers.update` 확장 |
| `fs.copy { from, to, recursive }` + 진행 이벤트 | EXP-83 | |
| `fs.remove { path, trash }` → `trash` 의 OS 지원 여부 | EXP-84 | `fs:write` 어휘의 "삭제" 와 맞춘다 |
| `fs.list { cursor, limit }` 또는 스트리밍 | EXP-09 | 10만 항목 폴더. 선택 사항 |

## 하지 않는 것

- 파일 내용을 읽거나 보여 주지 않는다 — 미리보기는 `viewer`, 편집은 opener 의 일.
- 검색(이름 · 내용)은 별도 플러그인(`search`) 또는 팔레트의 항목 검색(#97) 에.
- 즐겨찾기 · 태그 · 최근 폴더 — 1단계엔 없다. 최근 *파일* 은 `desk.files.recent` 가 이미 한다.
- 터미널 열기, OS 파일 관리자에서 보기 — `proc:spawn` 이 필요하고 탐색기의 권한 폭을 넓힌다. 별도 커맨드 플러그인으로.
- 네트워크 · 클라우드 드라이브 — 브리지의 fs 는 로컬 디스크다.

## 열린 질문

- **왼쪽 가장자리의 자리**: 셸의 샘플 프로필에서는 왼쪽이 에이전트 바(시스템 층, ADR 0023)다. 탐색기의 `left` 표면이 그 옆에 서는지, 셸 프로필이 탐색기를 끄고 `Mod+Shift+E` 로만 띄우는지는 ADR 0028 의 결정을 따른다. 지금은 두 가장자리 플러그인(`sidebar` 와 탐색기)이 같은 자리에 쌓인다.
- **기본 폴더**: `~/Documents` 하나로 시작한다(셸 모드의 Eris 범위 기본값과 같다). `~` 전체는 허락 요청의 폭이 너무 넓어 첫 경험에 맞지 않다고 봤다. 첫 실행 시나리오가 폴더를 고르게 하면 그 값을 쓴다.
- **`desk.files` 로의 흡수**: 정책과 UI 를 한 플러그인에 두면 "탐색기만 갈아끼우기" 가 어려워진다. 지금의 분리를 유지하되, `desk.files` 가 `role:file-browser` 같은 역할 슬롯(BR-05)을 선언하는 날 다시 본다.
- **심링크**: 지금은 링크로 표시만 하고 열기는 opener 에 맡긴다. 루프(자기 부모를 가리키는 링크)는 펼치지 않으니 안전하지만, `fs.stat` 이 오면 폴더 링크를 펼칠지, 범위 밖을 가리키는 링크를 어떻게 적을지 정해야 한다.
