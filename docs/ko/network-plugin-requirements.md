# endue 네트워크 플러그인 요구사항

2026-11-17 · Team endue

> 우리 집 네트워크를 보여 주는 기본 플러그인 `endue.network`(`plugins/network`) 가 무엇을 해야 하는지를 번호를 붙여 적은
> 문서입니다. `desk-requirements.md` 의 BASE 표에서 한 줄(`network`)을 차지하고, 이 문서가 그 줄을 펼칩니다. 요구사항 한 줄이
> Task 이슈 하나의 요구사항 칸이 됩니다. 왜 macOS 기본 프로그램과 `net.connect` 만 쓰고 지금 붙은 사설 대역만 보는지는
> ADR 0266 이, 코드가 하는 일은 `plugins/network/README.md` 가 말합니다. *현재* 열은 이 문서와 함께 들어간 첫 판(0.1.0) 기준입니다.

좋은 네트워크 표면의 값어치는 셋입니다. 지금 연결된 네트워크에 **누가** 붙어 있는지, 그 네트워크가 **안전한지**, Wi-Fi 가 **왜
느린지**를 그림으로 한눈에 보여 줍니다. 그리고 기기 목록에서 끝나지 않고 *무슨 뜻인지, 뭘 하면 되는지*를 문장으로 말합니다.
endue에서는 하나가 더 붙습니다. 모든 동작이 커맨드라 Eris 가 "지금 누가 붙어 있어?" 에 같은 길로 답합니다.

## 명칭

명칭은 표준 용어를 그대로 씁니다: IP 주소, MAC 주소, 제조사, 포트, Wi-Fi 채널, 핑(ms), 보안 방식, mDNS 이름, 무작위 MAC 주소,
공유기, 혼잡도, 신호 세기(dBm). 용어마다 한 줄 풀이(`help.*`)를 도움말로 붙입니다. 방 · 문 · 도로 비유는 **그림의 짜임에만**
씁니다. 기기는 지붕 선 아래 평면도의 칸처럼 공유기를 가운데 두고 배치하고, 열린 포트는 반쯤 열린 틀 모양 아이콘으로, 채널은
나란한 세로 줄(차선 그림)로 그립니다. 라벨 · 제목 · 커맨드 이름 · 메시지에는 비유 낱말(방 번호 · 명찰 · 문 · 차선 · 도로)을
쓰지 않고, `tests/messages.test.ts` 가 en · ko 카탈로그와 매니페스트에서 이를 확인합니다.

## 표준

| 표준 | 어디에 | 요구사항 |
| --- | --- | --- |
| RFC 1918 (사설 IPv4 대역) | 훑기 · 핑 · 포트 점검이 가는 곳은 10/8 · 172.16/12 · 192.168/16 안, 지금 붙은 대역뿐 | NET-02 · NF-01 |
| IEEE OUI 등록부 (MA-L) | MAC 주소 앞 24비트로 제조사. `assets/oui.txt`, `dev/make-oui.mjs` 가 만든다 | NET-06 |
| IEEE 802 로컬 관리 비트 | 첫 옥텟의 0x02 가 켜진 MAC 주소는 무작위 MAC 주소 | NET-06 |
| mDNS (RFC 6762) 역방향 질의 | `dig -x <IP> -p 5353 @224.0.0.251` 로 기기 이름 | NET-05 |
| IEEE 802.11 채널 계획 | 2.4 GHz 1–13(5 MHz 간격, 20 MHz 폭), 5 GHz 36–165 · 6 GHz 1–233(20 MHz 단위, 40/80/160 MHz 묶음 정렬) | NET-12 |
| RFC 3339 | 처음 · 마지막으로 본 때, 일지의 시각 | NET-05 · 15 |

## 약속

| # | 약속 | 뜻 | 지키는 요구사항 |
| --- | --- | --- | --- |
| 1 | 셸 없이 OS 기본 프로그램만 | `proc:spawn` 은 여섯 프로그램의 전체 경로(`/usr/sbin/arp` · `/sbin/ping` · `/sbin/route` · `/sbin/ifconfig` · `/usr/bin/dig` · `/usr/sbin/system_profiler`). 인자는 배열. nmap · Npcap 은 넣지도 부르지도 않는다 | NET-01 · NF-01 |
| 2 | 지금 붙은 사설 대역만 | 공인 IP · 다른 대역 · 링크 로컬 · 네트워크/브로드캐스트 주소는 코드에서 거절(`ipv4.js`). /24 보다 큰 대역은 훑지 않고 ARP 표만 | NET-02 · 03 |
| 3 | 관리자가 아니면 훑지 않는다 | 첫 점검 전에 "이 네트워크의 관리자인가요?" 를 네트워크마다 한 번(공유기 MAC 주소로 구분). 아니면 ARP 표와 공유기 핑만 | NET-03 |
| 4 | 포트는 묻고, 닿기만 한다 | 자주 쓰는 38개만 `net.connect`, 연결되면 바로 닫고 아무것도 보내지 않는다. 기기마다 `perm.request`(endue.screens 와 같은 길) | NET-08 |
| 5 | Wi-Fi 는 듣기만 | `system_profiler SPAirPortDataType -json` 을 읽을 뿐 접속 시도는 없다. 가려진 SSID 는 가린 채로 | NET-12 · 14 |
| 6 | 결과는 이 컴퓨터에만 | 플러그인 store, 값 하나 64 KiB 안. 일지는 최근 것만 | NET-17 |
| 7 | 두뇌에는 사실만 | "쉽게 설명해 줘" 는 기기 종류 · 제조사 · 열린 포트 · 점수 항목만 넘긴다. 사람이 붙인 이름 · 주변 SSID · 주소는 넘기지 않는다 | NET-16 |
| 8 | 못 하면 말로 | 공인 IP · 다른 대역 · 관리자 아님 · 권한 거절 · 프로그램 없음 · 다른 OS · Wi-Fi 꺼짐을 정해진 문장과 할 일로 | NF-02 |

## 빌린 개념

네트워크 스캐너 앱 · Wi-Fi 분석기 · 공유기 관리 화면의 관용을 빌리고, 커맨드 · 알림 · 타임라인은 endue의 것으로 바꿔 답니다.

| 관용 | endue `endue.network` | 요구사항 |
| --- | --- | --- |
| 스캐너 앱의 기기 목록(IP · MAC · 제조사) | 지도 아래 모든 기기 표 + 기기 카드 | NET-04 · 05 |
| 기기에 이름 붙이기 · "내 기기" 표시 | "이 기기는 누구예요?" 로 이름 · 종류 · 내 기기. 붙이면 아는 기기 | NET-07 |
| 새 기기 알림 | 처음 보는 기기를 `ui:notify` 로(네트워크의 첫 훑기는 알리지 않는다) | NET-15 |
| 보안 점수와 할 일 | 100점 만점, 항목 셋, 무거운 것부터 할 일 카드 | NET-09~11 |
| Wi-Fi 분석기의 채널 그래프 | 대역별 채널 줄 그림, 겹침을 넣은 혼잡도, 권장 채널 문장 | NET-12 · 13 |
| 공유기의 접속 기록 | 새 · 돌아온 · 사라진 기기를 universal timeline 으로 | NET-15 |

## 아키텍처 매핑

- **종류**: `kind: ui`, `autoload`(열 때까지 꺼져 있다). 파싱 · 모델은 JS, 권한 경계는 브리지 하나.
- **권한**: `proc:spawn { commands: [여섯 경로] }`, `ui:notify`, `brain:ask`. `net:connect` 는 매니페스트에 없고 기기마다
  `perm.request { permission: net:connect, hosts: [<IP>:<포트> × 38] }`. `fs:*` · `shell:open` · `cmd:invoke` 는 없다.
- **표면**: `main` 하나(`center`), 탭 넷: 지도 · 점검 · Wi-Fi 채널 · 일지. 기기 카드는 같은 표면의 옆 칸.
- **말**: `messages/en.json` · `ko.json`(ADR 0250, `ctx.messages`). `data-t` 와 그리는 코드가 모두 카탈로그에서 읽는다.
- **기여**: 커맨드 7(`endue.network.*`) · 설정 1(`endue.network.interval`, 분, 기본 5, 0 이면 끔).
- **실행 모델**(`ui/run.js`): 프로그램마다 `proc.spawn` 하나, 전체 경로, `proc:spawn` 범위는 그 프로그램 하나. 권한이 없으면 여섯 모두를
  한 번 묻는다. `not_found` 는 그 프로그램 이름으로 거절. 핑 · dig 는 열여섯씩 동시에, system_profiler 는 40 초.
- **모듈**: 주소와 읽기(`ipv4` · `parse` · `wifi` · `oui` · `run` · `probe`), 모델(`devices` · `kinds` · `layout` · `ports` · `checkup` ·
  `channels` · `journal`), 컨트롤러(`network` · `app` · `commands` · `explain` · `store` · `refusal`), 화면(`view*` · `labels` · `dom` ·
  `icons` · CSS 셋). 파일마다 400 줄 이하.

## 요구사항

### 기능 (NET)

| ID | 요구사항 | 현재 | 단계 |
| --- | --- | --- | --- |
| NET-01 | 기본 프로그램: `route -n get default`(공유기 · 인터페이스), `ifconfig <인터페이스>`(내 IP 주소 · 넷마스크 · MAC 주소), `arp -an`(ARP 표), `ping -n -q -c 1 -W 800 -t 2 <IP>`, `dig -x <IP> -p 5353 @224.0.0.251 +short +time=1 +tries=1`(mDNS 이름), `system_profiler SPAirPortDataType -json`(Wi-Fi). 셸 없음, 인자 배열, 전체 경로. arp 의 앞자리 0 빠진 MAC 주소는 채운다 | 있음 | A |
| NET-02 | 대역 제한: 기본 경로의 인터페이스 대역이 RFC 1918 사설 대역이어야 한다. 공인(CGNAT · 링크 로컬 포함)이면 거절. 핑 · dig · 포트 점검 전에 대상마다 `targetRefusal` — 공인 · 다른 대역 · 네트워크/브로드캐스트 주소 · 잘못된 주소는 프로그램을 부르기 전에 거절 | 있음 | A |
| NET-03 | 관리자 질문과 훑기: 네트워크(공유기 MAC 주소, 없으면 공유기 IP)마다 한 번 "이 네트워크의 관리자인가요?". 예 + /24 이하면 내 주소를 뺀 모든 주소에 핑(훑기) 뒤 ARP 표를 다시 읽고 mDNS 이름을 묻는다. 예 + /24 보다 크면 훑지 않고 ARP 표의 기기에만 핑. 아니요 · 아직이면 ARP 표와 공유기 핑만. 답은 지도 위의 카드에서 바꿀 수 있다 | 있음 | A |
| NET-04 | 지도: 지붕 선 아래 평면도, 홀수 칸 격자 가운데에 공유기, 둘레에 기기(가까운 고리부터, 고리 안에서는 가까운 칸부터 위에서 시계 방향). 공유기에서 기기마다 선. 상태 셋: 아는 기기(초록 · 원에 체크 · "아는 기기"), 새 기기(노랑 · 마름모에 물음표 · "새 기기" · 점선 테두리), 주의(빨강 · 세모에 느낌표 · "주의" · 굵은 테두리). 색만으로 가르지 않는다. 80대 넘으면 나머지는 아래 표에. 지금 없는 아는 기기 수 | 있음 | A |
| NET-05 | 기기 카드: 이름(사람이 붙인 것 › mDNS 이름 › "IP 의 종류"), 종류(추정이면 "(추정)"), IP 주소, MAC 주소, 제조사, mDNS 이름, 핑(ms 와 빠름 <20 · 보통 <100 · 느림 · 답 없음), 처음 · 마지막으로 본 때, 열린 포트. 지도 아래 모든 기기 표에도 같은 열 | 있음 | A |
| NET-06 | 제조사: IEEE OUI(MA-L) 등록부를 `assets/oui.txt`(약 4만 줄, 800 KB)로 싣고 프레임이 직접 읽는다(권한 없음). 로컬 관리 비트가 켜진 MAC 주소는 제조사 대신 "무작위 MAC 주소(휴대폰일 수 있음)" | 있음 | A |
| NET-07 | "이 기기는 누구예요?": 이름(60자) · 종류(열네 가지) · 내 기기. 답하면 아는 기기가 된다. 종류는 사람이 정하기 전까지 mDNS 이름 › 제조사 › 열린 포트 › 무작위 MAC 순으로 추정 | 있음 | A |
| NET-08 | 포트 점검: 관리자일 때만, 기기마다 `perm.request`(그 IP 의 38 포트). 넷씩 `net.connect`(1.2 초), 연결되면 바로 `net.close`, 아무것도 보내지 않는다. 열림 · 닫힘(`io_error`) · 조용함(`timeout`)을 센다. 거절되면 그 기기의 포트에 닿지 않는다. "모든 기기의 포트 점검" 은 기기마다 차례로 묻는다 | 있음 | A |
| NET-09 | 점검 화면: 100점 만점 점수(고리 그림과 숫자), 등급(좋음 ≥90 · 보통 ≥70 · 손볼 것이 있음), 항목 셋과 각각 깎인 점수, 산식 한 줄 | 있음 | A |
| NET-10 | 점수 산식: 100 − 모르는 기기(지금 붙은 새 기기 대당 5, 최대 25) − 위험한 열린 포트(Telnet 23 · 2323, FTP 21, SMB 139 · 445, RDP 3389, VNC 5900 · 5901 은 15, 80 · 443 밖의 관리 화면 81 · 7547 · 8000 · 8080 · 8081 · 8443 · 8888 · 10000 은 8 — 공유기의 관리 화면은 빼고, 최대 50) − 내 Wi-Fi 의 보안 방식(보안 없음 · WEP 25, WPA 15, WPA/WPA2 혼합 10, WPA2 · OWE 5, WPA3 · 엔터프라이즈 0, 최대 25). 이 네트워크가 이 컴퓨터가 붙은 Wi-Fi 가 아니면(유선) 0 과 그 이유, Wi-Fi 를 아직 못 읽었으면 0 과 "아직" | 있음 | A |
| NET-11 | 할 일 카드: 위험한 포트마다 "거실 카메라: 포트 23(Telnet) 열림." 과 서비스별 닫는 법(기기 관리 화면에서 끄기 · 펌웨어 · 공유기의 포트 포워딩 규칙 지우기), 모르는 기기, Wi-Fi 보안 방식, 점검하지 않은 기기. 깎인 점수가 큰 것부터(같으면 포트 › Wi-Fi › 모르는 기기). 그림은 기기마다 열린 포트 아이콘, 라벨은 포트 번호와 서비스 이름 | 있음 | A |
| NET-12 | Wi-Fi 채널: 2.4 · 5 · 6 GHz 를 따로 그린다. 채널마다 세로 줄, 네트워크마다 덮는 채널에 걸친 막대(겹치지 않게 줄을 나눈다), 내 Wi-Fi 는 강조, 권장 채널에 깃발. 6 GHz 는 네 칸마다 번호 | 있음 | A |
| NET-13 | 혼잡도: 채널 k 의 부하 = Σ(네트워크가 k 를 덮는 비율 × 세기). 2.4 GHz 는 5 MHz 간격 20 MHz 폭의 주파수 겹침(이웃 채널 0.75 · 0.5 · 0.25), 5 · 6 GHz 는 정렬된 묶음 안이면 1. 세기는 (dBm + 90) / 40 을 0.2–1 로, 모르면 0.6. 부하 <1 여유 · <2.5 붐빔 · 그 이상 혼잡. 권장은 2.4 GHz 1 · 6 · 11, 5 GHz 36–48 · 149–161(DFS 제외), 6 GHz PSC 중 내 폭으로 덮을 묶음의 부하가 가장 작은 것. 내 채널이 여유가 아니고 권장이 1 이상 덜 붐비면 "채널 6 혼잡, 채널 11 권장." | 있음 | A |
| NET-14 | 가려진 SSID: 위치 서비스 권한이 없어 macOS 가 SSID 를 `<redacted>` 로 주면 채널만 그리고 이유와 할 일(시스템 설정 › 개인정보 보호 및 보안 › 위치 서비스)을 문장으로. 내 Wi-Fi 의 채널 · 폭 · 신호 · 잡음 · 속도는 따로 한 줄 | 있음 | A |

## 가정과 결정 (뒤집으려면 거절에 한 줄로)

1. `kind: ui`, id `endue.network`, 이름 Network(네트워크), 표면 하나, `autoload`.
2. 네트워크의 열쇠는 공유기의 MAC 주소(`gw-<12 hex>`), ARP 표에 없으면 공유기 IP(`ip-…`).
3. 관리자가 아니라고 해도 ARP 표(OS 가 이미 아는 것)와 공유기 핑 하나는 보여 준다. 훑기 · mDNS 질의 · 포트 점검은 하지 않는다.
4. /24 보다 큰 대역에서 관리자라고 하면 ARP 표의 기기에만 핑을 보낸다(훑기가 아니다).
5. 포트 38개: 21 · 22 · 23 · 25 · 53 · 80 · 81 · 110 · 139 · 143 · 443 · 445 · 515 · 548 · 554 · 631 · 1883 · 2323 · 3000 · 3306 · 3389 · 5000 · 5432 · 5900 · 5901 · 6379 · 7000 · 7547 · 8000 · 8008 · 8080 · 8081 · 8443 · 8888 · 9100 · 10000 · 32400 · 62078.
6. 공유기의 80 · 443 · 관리 화면 포트는 위험으로 세지 않는다(공유기 설정 화면은 원래 있다).
7. "모르는 기기" 는 지금 붙어 있는 새 기기. 공유기와 이 컴퓨터는 늘 아는 기기.
8. 사라짐은 15 분, 기기 기록은 300대, 일지는 400개 · 60 KiB.
9. 네트워크의 첫 훑기는 새 기기를 하나씩 알리지 않는다(이미 있던 기기들이다).
10. 커맨드 `channels` 와 `log` 의 답에도 SSID 는 넣지 않는다(에이전트의 답은 두뇌로 간다). `devices` 는 사람이 붙인 이름을 답한다 — Eris 가 "누가" 에 답해야 하므로.
