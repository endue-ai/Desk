# Testing

Which tests run for which change, and where they live. The layers come from the design
(`docs/ko/desk-structure.md`, "QA: 테스트 층"). Layers are switched on when they have something real to
catch; until then they are marked "not yet".

## Rules

- A task adds its tests to its own crate's or area's row of the layers table: one row per crate for
  Integration (Rust), one per area for Runtime (web), so parallel PRs touch different lines.
- Tests live next to the source. Acceptance tests for a task go in `crates/<crate>/tests/` or `*.test.ts`
  so red-on-base can run them on the base commit; inline Rust tests are reported but not checked there.
- Animations run on an injected clock and randomness takes a seed. Snapshots are taken at fixed times.
- Timing tests choose their own quiet periods, wide enough for a loaded runner, instead of relying on
  defaults (`watch_coalesces_a_burst_into_one_batch` debounces for 1 s, not the default 100 ms).
- Test helpers that build temp paths include a process-wide counter next to the process id, never the
  clock alone: tests run in parallel threads, and the clock can hand two of them the same path (#106).
- Test hooks (`desk.test.*`) exist only behind the `test-hooks` feature, never in release builds.
- Playwright runs only through `just test-e2e` and `just perf-opening` (ADR 0018). On macOS the
  runtime e2e runs in a Linux container, at most two e2e runs share a machine, and native WebKit is
  for people only (`DESK_E2E_NATIVE=1`); the Playwright configs refuse anything else.
- The app e2e (WebdriverIO, not Playwright) runs only on Linux through `just test-app-e2e` and
  `just smoke`; on macOS both refuse (ADR 0006). Its `*.spec.ts` files are not seen by red-on-base,
  so a new app spec is proven by its pass in the `e2e` workflow on the PR.
- No test asks the OS for calendar or reminder access. The one EventKit test
  (`crates/desk-sys/tests/calendar.rs`, `on_macos_the_os_source_lists_real_calendars_when_access_is_granted`)
  is `#[ignore]`d because it reads the person's calendars: people run it on a Mac with access granted,
  `cargo test -p desk-sys --all-features --test calendar -- --ignored`.
- A test that still flakes after three retries gets the `quarantine` label and an issue. Quarantined
  tests do not block merges but keep running nightly.
