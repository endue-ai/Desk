# Testing

Which tests run for which change, and where they live. The layers come from the design
(`docs/ko/desk-structure.md`, "QA: 테스트 층"). Layers are switched on when they have something real to
catch; until then they are marked "not yet".

## Layers

Image opening regressions: `just test-e2e image-files.spec.ts` loads the real Images and Explorer
plugins in the shell under the plugin CSP. It checks JPEG/PNG rendering, single-click opening while
Images is off, reopening after close, and opening the same or another image from the drawer. The
runtime's `plugin-reconnect.test.ts` checks requests wait for the recreated frame; Images'
`files.test.ts` checks surviving buffers reload without reopening buffers already closed.

## Rules

- A task adds its tests to its own crate's or area's row of the layers table: one row per crate for
  Integration (Rust), one per area for Runtime (web), so parallel PRs touch different lines.
- Tests live next to the source. Acceptance tests for a task go in `crates/<crate>/tests/` or `*.test.ts`
  so red-on-base can run them on the base commit; inline Rust tests are reported but not checked there.
- Animations run on an injected clock and randomness takes a seed. Snapshots are taken at fixed times.
- Timing tests choose their own quiet periods, wide enough for a loaded runner, instead of relying on
  defaults (`watch_coalesces_a_burst_into_one_batch` debounces for 1 s, not the default 100 ms).
- Test helpers that build temp paths include a process-wide counter next to the process id, never the
  clock alone: tests run in parallel threads, and the clock can hand two of them the same path (#106).
- Test hooks (`desk.test.*`) exist only behind the `test-hooks` feature, never in release builds.
- Playwright runs only through `just test-e2e` and `just perf-opening` (ADR 0018, ADR 0144). The
  runtime e2e runs headless Chromium natively on every OS, four workers a run at most, on Chrome for
  Testing's headless shell of the CEF desk's own build (`packages/runtime/e2e/chromium.ts`, pinned in
  `e2e/driver/chrome-for-testing.json` and fetched on the first run; Playwright's bundled build of the
  same branch killed a frame's renderer when a just-created field took the focus); on macOS the
  Playwright configs refuse a run the runner did not start, and an agent's `--headed`, `--ui` or
  `--debug`, which open windows on WindowServer. One e2e invocation at a time per task. Measured on
  this change (#48): a full run with four workers kept 17 Chromium processes and 2.6 GB RSS at most,
  owned no WindowServer window, and left WindowServer's RSS flat. Render trees with text-sized boxes
  follow the fonts installed (two such snapshots read 34 and 541 px on macOS, 39 and 554 on Linux):
  the committed ones are Linux's, which CI gates on.
- The app e2e (WebdriverIO, not Playwright) runs through `just test-app-e2e` and `just smoke` on the
  CEF desk on macOS, Linux and Windows (ADR 0144; `just build-shell` first). Its `*.spec.ts` files are not seen by
  red-on-base, so a new app spec is proven by its pass in the `e2e` workflow on the PR.
- No test asks the OS for calendar or reminder access. The one EventKit test
  (`crates/desk-sys/tests/calendar.rs`, `on_macos_the_os_source_lists_real_calendars_when_access_is_granted`)
  is `#[ignore]`d because it reads the person's calendars: people run it on a Mac with access granted,
  `cargo test -p desk-sys --all-features --test calendar -- --ignored`.
- No test reads or writes the person's clipboard. The one OS clipboard test
  (`crates/desk-sys/tests/clipboard.rs`, `the_os_clipboard_writes_reads_and_marks_text`) is `#[ignore]`d
  because it replaces the clipboard for a moment: people run it on a Mac and on Windows before approving a
  change to the OS clipboard, `cargo test -p desk-sys --all-features --test clipboard -- --ignored`.
- No test reads this computer's proxy settings in the default run. The OS readers' tests
  (`crates/desk-sys/tests/net_proxy.rs`, `on_macos_system_settings_match_scutil` and
  `on_windows_system_settings_match_the_registry`) are `#[ignore]`d: people run them on a Mac and on
  Windows before approving a change to those readers,
  `cargo test -p desk-sys --all-features --test net_proxy -- --ignored`.
- No test opens a microphone or asks the OS for one. The capture tests use `FakeInput`, the OS test
  (`the_os_input_answers_on_this_platform`) lists devices and reads the grant without prompting, and the
  one real capture (`crates/desk-sys/tests/audio.rs`,
  `on_this_computer_the_os_input_captures_the_default_microphone`) is `#[ignore]`d: people run it with a
  microphone and the OS permission, `cargo test -p desk-sys --all-features --test audio -- --ignored`.
  Linux builds need the ALSA headers (`libasound2-dev`), which `check (linux)` installs.
- No test synthesizes input, performs an AX action, prompts for a TCC permission or captures the screen in
  the default run: computer use is tested through `FakeComputer`. The real-OS checks
  (`crates/desk-computer/tests/macos.rs`) are `#[ignore]`d and read only; people run them on a Mac before
  approving a change to the macOS driver, `cargo test -p desk-computer --test macos -- --ignored`, once
  with Accessibility and Screen Recording granted to the terminal and once without.
- No test posts an OS notification or asks the OS for notification permission: the notifier tests use
  `FakeNotifier`, macOS's only checks the refusal outside an app bundle, and the freedesktop tests talk
  to a server in the test process.
- A test that still flakes after three retries gets the `quarantine` label and an issue. Quarantined
  tests do not block merges but keep running nightly.
